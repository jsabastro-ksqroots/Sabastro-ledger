| P0-1  | **Line amounts are stored as non-negative `debit_cents` and `credit_cents`, exactly one non-zero per line.** The importer converts a negative debit in the source into a positive credit (and vice-versa). Net totals per account and per class are unchanged; the **gross** debit and credit totals each rise by Σ\|negative amounts\| = **5,862.32**, so the 2019–2024 gross target after normalisation is **13,303,638.68 = 13,303,638.68**. Phase 2 reconciles on net per account and per class × sub-type, and reports both gross figures.                                                    | 43 lines in the 2019–2024 workbook carry negative debits. Two non-negative columns make the balance rule and the reports unambiguous.                           |
| P0-2  | **Balance is enforced per entity within each transaction**, over live lines, not just per transaction.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Guarantees each entity's books balance on their own, which is the whole point of the bridge rule. Implies the global balance.                                   |
| P0-3  | The four zero-amount single-line 2024-07-12 bank-fee entries (transactions 2623–2626) import as `VOIDED` transactions **with no lines**, keeping account/name/memo in the header and a system note, with reason "zero-amount placeholder in source workbook". | P0-9  | **Sessions:** 32 random bytes, base64url in the cookie `sl_session`, SHA-256 hash in the table; `HttpOnly; Secure (outside localhost); SameSite=Lax; Path=/`. Fully open sessions: idle expiry 12 h, absolute 7 days. **Half-open sessions (password ok, code pending) expire after 10 minutes and are only accepted by the MFA pages; when the code passes, the token is rotated.**                                                                                                                                                                                                               | CLAUDE.md fixes the idle rule; the short half-open life and the rotation stop a stolen password from becoming a week-long foothold.                             |
| P0-10 | **Rate limiting / lockout:** wrong passwords, wrong authenticator codes and wrong recovery codes all count. 5 failures per user in 15 minutes locks the account for 15 minutes (doubling each repeat, max 24 h); 30 failures per IP in 15 minutes throttles that IP. The lock is checked before any password hash or code is computed. All attempts are logged.                                                                                                                                                                                                                                    | CLAUDE.md asks for "rate-limit and lock out after repeated failures"; a 6-digit code must not be brute-forceable from a half-open session.                      |
| P0-11 | **MFA:** TOTP (SHA-1, 6 digits, 30 s, ±30 s tolerance), secret encrypted with AES-256-GCM under `TOTP_ENCRYPTION_KEY` (12-byte random nonce per encryption, versioned `v1:` prefix); the last accepted time step is stored so a code cannot be replayed; 10 recovery codes (10 chars, Argon2id-hashed, single use). Enrollment is forced: an un-enrolled user can only reach the enrollment screen. An administrator can reset another user's MFA (audited, target's sessions end); nobody resets their own.                                                                                       | Standard authenticator-app parameters; recovery codes are the "no SMS" fallback.                                                                                |
| P0-12 | **Roles → permissions:** `OWNER` and `FULL` = every permission incl. `manage_users` and `close_year`; `LIMITED` = the checklist stored in `user_permissions` (now including `close_year`); `VIEW_ONLY` = `view_ledger` + `run_reports`. **Owner-only**, beyond permissions: remove users, change owner, re-open a closed/filed year, re-apply a model to a filed year (D10).
